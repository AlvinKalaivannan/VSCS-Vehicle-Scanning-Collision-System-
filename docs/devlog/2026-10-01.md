## Session 04:04 — task P2-T3 / P2-T5 plumbing (`scripts/fuse.py`)

**Goal:** close the one gap in the offline chain that is plumbing, not core: turning 2D masks
plus the dense workspace into the labelled points `export_model.py` reads.

**What I did:**

- `seg/fuse_inputs.py`:
  - COLMAP dense `.bin` reader and writer;
  - `SfmToVeh` (scale + `T_veh_world`), which maps points, poses and depths from SfM
    units into metric `veh`;
  - view loading. It refuses non-pinhole cameras, masks whose size differs from the depth
    map (the "masks made on the original frames" mistake), and mask labels beyond the
    named components.
- `scripts/fuse.py`:
  - calls the developer's `fusion3d` through a `FUSION` hook, and stops with exit 3 and
    no run folder while it is missing or a stub;
  - sums votes over batches of views (`seg.yaml fusion3d.views_per_batch`, memory only);
  - then runs cleanup and writes `fused.npz`, `cleaned.npz` and `fuse_summary.json`.
- `recon/dense.py`: a fourth step, `model_converter` → `dense/sparse_txt`. The undistorted
  cameras, which match the depth maps, are written as binary, and `colmap_io` reads text.
- `20_seg.ipynb` now points at `<dense run>/dense/images`. It pointed at the original
  frames, which would have misaligned with the depth maps.
- The runbook and the CLAUDE.md §12 quick reference are updated.

**Evidence:** `tests/unit/test_fuse_inputs.py` (16 tests). It uses the fixture scene in a
rotated, shifted, 4×-scaled synthetic SfM frame; the loader recovers the true `veh` poses
(1e-9), depths (float32) and masks exactly. The CLI test uses a truth-voting stand-in, not
a fusion algorithm. Full suite: 793 passed, 1 skipped.

**For the developer (not decided):**

- **Missing depth.** COLMAP writes 0 where it has no depth; the `PosedView` contract
  turns that into `inf`, meaning "no surface". So a far-side point projecting onto a
  pixel the geometric filter emptied (glossy panels, R-01) passes the depth test and
  votes. Two options for your `observe`: treat missing depth as "cannot tell", so the
  frame does not vote; or keep it as is and rely on the vote fraction. Worth a test either
  way.
- **The `sfm_to_veh.json` format** (`{"scale", "T_veh_world"}`) is my proposal for what
  P1-T6 hands over. Your `scale.py` plus `vehicle_frame.py` produce exactly these two
  things.

## Session 04:16 — task P2-T3/T4/T5 scoring (`scripts/score_labels.py`)

**Goal:** the P2-T3, P2-T4 and P2-T5 gates had thresholds in `eval.yaml` but nothing that
computed them.

**What I did:**

- `eval/labels3d.py`:
  - reads a CloudCompare ASCII export (`x y z [extra columns] label`);
  - matches each gold point to its twin in the labelled cloud within 1 mm
    (`eval.yaml labels3d.match_tolerance_m`);
  - scores with the existing `per_component_iou`.

  Gold points with no twin are counted and reported. A gold set from another frame is
  refused.
- `scripts/score_labels.py`: scores `fused.npz` and `cleaned.npz` from a fuse run, checks
  the three gates, and appends `labeled_points_count` (P2-T4), `component_iou_mean` (P2-T3)
  and `component_iou_mean_cleaned` (P2-T5).
